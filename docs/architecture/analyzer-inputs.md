# Подготовка и сохранение нормализованных входов

Реализация [#18479](https://ai.nsu.ru/issues/18479) поверх
[исполнителя #18476](analyzer-execution.md). Форма снимка и значения полей заданы
[контрактом Analyzer](../../contracts/analyzer/v1/schemas.json) и
[MetricInput](../fields/common.md#metricinput); wire-модели не меняются.

## Подключение

`application/snapshot.Processor` реализует `worker.Processor`.
`app.RunWithInputs(ctx, collectors, calculator)` связывает его с очередью,
Git-сеансом и существующим хранилищем. Порты `Collector` и `Calculator`
объявлены в пакете-потребителе `application/snapshot`.

Collector получает принятое задание и безопасный Git-сеанс. Он возвращает
`Collection`: типизированные MetricInput с перечнем использованных Source scopes,
SourceState, Dependency и Vulnerability. Каждый вход ссылается на существующий
scope; дубликаты ID метрик и пары source/scope отклоняются. Git refs и исходные
Git scopes берутся только из сеанса; заменять их коллектор не может.
Для дополнительного Git-охвата используется отдельный scope.

Ошибку независимого источника коллектор представляет состоянием
partial/unavailable/not_applicable с безопасной причиной. Ошибка возврата
`Collect` означает невозможность продолжить сборку, а не пустой успешный ответ.
Текст HTTP-ответа, stderr или содержимое файла не должны попадать в Reason.
Контекст ограничивает коллекторы общим бюджетом обработки; отменённая обработка
не передаёт результат калькулятору.

`Build` собирает все 12 входов в порядке контракта. Отсутствующий вход получает
raw_value=null, status=unavailable, reason=INPUT_NOT_COLLECTED. Его время
наблюдения, размер выборки и полное число evidence остаются null. Для оконных
метрик используется исходное окно задания; чужое окно отклоняется.
Единицы задаются контрактными идентификаторами, без пересчёта исходных значений.
Числа, false, неизвестность, серии и отдельные причины исключения сохраняются.

Полный вход, зависящий от partial scope, становится partial с причиной этого
ограничения. Заявление complete при unavailable/not_applicable scope отклоняется.
Коллектор обязан сам определить, допустимо ли численное значение на неполном
охвате по методике; сборщик не вычисляет агрегат из усечённой выборки.
Время получения берётся от источника и приводится к UTC с точностью PostgreSQL.
Неизвестное время не заменяется моментом сборки, assessment_at или time.Now().

Calculator получает отдельную копию готового SnapshotData. Он рассчитывает
ReportData по этим входам без новых обращений к Git/GitHub/OSV. Полученный отчёт
проходит существующую валидацию соответствия сохранённым входам. Сборщик не
добавляет оценки, находки, рекомендации или фиктивный fallback вместо калькулятора.

## Публикация и безопасность

Owner, analysis_id, repository, t, окно и версии принадлежат принятому заданию.
Коллекторы не задают их в Collection. Сеанс другого репозитория/SHA отклоняется.
Времена completed_at и идентификаторы snapshot/report формирует хранилище при
успешной публикации. Снимок, отчёт и completed сохраняются одной транзакцией;
отдельного промежуточного снимка и новых миграций нет.

Зависимости дедуплицируются по ecosystem/package/version с сохранением всех
origins; первичный origin выбирается в стабильном лексикографическом порядке.
Лимит 20 применяется к уникальным зависимостям. Превышение не обрезается молча:
коллектор должен вернуть разрешённую выборку и соответствующее ограничение.
OSV-находки дедуплицируются по vulnerability_id/ecosystem/package/version;
при одинаковых сведениях сохраняется последнее фактическое obtained_at.
Противоречивые severity/ссылки отклоняются; неизвестная severity остаётся null.

RawValue допускает только scalar. Для SEC_SECRETS текстовое значение запрещено.
Описание secret_match канонизируется по типу: свободный текст найденной строки
не сохраняется. Существующая валидация проверяет безопасные пути/HTTPS-ссылки,
ревизии и ссылки уязвимостей на сохранённые зависимости. Исходные файлы, токены,
пароли и сессионные реквизиты отсутствуют в моделях Collection/Snapshot.
Снимок отделён от вложенных указателей/списков производителей и калькулятора.

Чтение выполняется через `storage.GetResult`: только PostgreSQL и проверка
исходного Owner. Оно не вызывает Collector/Calculator и не меняет t/версии,
даже если исходный Git или внешний источник изменился либо больше недоступен.

## Границы и проверка

Этот слой принимает результаты конкретных анализаторов; их правила, сбор
GitHub activity/CI, парсеры зависимостей/OSV и Score принадлежат соседним задачам.
Они не подменяются данными примеров. Обычный `cmd/analyzer` пока не настраивает
эти коллекторы и калькулятор; полный пользовательский анализ ещё не подключён.

Unit-тесты проверяют неизвестность/0/false, фактические времена, окно, частичный
охват, безопасные evidence, дедупликацию, отмену и изоляцию от изменения входов.
`TestNormalizedSnapshotIsPublishedAndReadOfflineForOriginalOwner` использует
отдельную PostgreSQL, весь worker → сборщик → storage, затем изменяет контрольный
источник и проверяет неизменяемое чтение, исходного владельца и единственную
согласованную публикацию. Калькулятор в этом тесте проверяет только публикацию,
не реализацию формул Score. Настройка тестовой БД описана в
[README backend](../../project/backend/README.md).
