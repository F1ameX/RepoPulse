# Сохранение и выдача отчёта активности

Реализация [#18491](https://ai.nsu.ru/issues/18491) связывает сборщик
[#18490](https://ai.nsu.ru/issues/18490), [расчёт #18488](activity-scoring.md),
[сборку снимка #18479](analyzer-inputs.md) и транзакционную публикацию #18467.
Поля ответа определены [контрактом Report](../../contracts/report/v1/schemas.json).

## Выполнение

Штатный `cmd/analyzer` подключает `application/activity.Processor`. Он получает
Git-сеанс с историей закреплённой ревизии, рассчитывает три метрики через
`scoring.Engine`, собирает `SnapshotData` и передаёт готовый `ReportData` исполнителю.
Метаданные владельца, ID анализа, repository, t, окно и версии берутся из принятого
задания. Git-объекты удаляются перед транзакцией snapshot/report/completed.

Сохраняются исходные значения и единицы, полные недельные счётчики, выборки,
нормализованные баллы, правило с параметрами, версия и порог. Evidence содержит
подтверждённые SHA и HTTPS-ссылки на коммиты. Для метрики сохраняется до десяти
оснований, признак ограничения и известное полное число оснований.

Неполная история сохраняет причину и известные наблюдения. Полный обход закреплённой
ревизии может независимо подтвердить последнюю дату при ограничении остальных refs.
Это доказательство записывается отдельным scope `git/activity_last_commit`.
Без такого доказательства последняя дата и её балл остаются неизвестными.
Подтверждённая пустая история получает отчёт с причинами неприменимости метрик.

Прочие девять метрик получают unavailable/null. Общий Score остаётся null с причиной
ACTIVITY_ONLY до реализации #18527. Категория activity содержит рассчитанный балл
и собственное покрытие. Каталог находок и рекомендаций относится к следующим задачам.

## Чтение

`GET /api/v1/reports/{report_id}` получает VerifiedContext через Auth.ResolveContext.
Gateway вызывает существующий бинарный RPC Report.GetReport и явно переносит поля
protobuf в HTTP JSON. HTTP DTO сохраняет snake_case, неизвестные скаляры и `[]`.
Баллы и Coverage.percentage отчёта/категорий округляются half-up до одного знака
только на публичной HTTP-границе.
Сырые значения, счётчики и сохранённый результат остаются в исходной точности.

Report Service читает `report.reports` и проверяет соответствие owner_id одному
из действующих проверенных контекстов. Исходный guest имеет доступ после входа,
пока действителен его собственный guest context. Чужой, отсутствующий и неверный
ID одинаково дают REPORT_NOT_FOUND. Истечение сессии даёт 401, недоступный Report
Service — 503 REPORT_UNAVAILABLE. Повторный GET можно выполнять с тем же report_id.

Чтение использует сохранённый JSON. Новый коммит, изменение внешнего источника,
повторное открытие страницы и F5 сохраняют ID, времена, входы, баллы и версии отчёта.
Версии и момент завершения формируются при принятии/публикации и берутся из БД.

## Запуск и проверка

Docker Compose задаёт Report Service адрес `report:9091`, DSN общей PostgreSQL
и ожидание успешных миграций. Сами приложения миграции не выполняют.
Для локального запуска см. [README backend](../../project/backend/README.md#report-service).

`TestActivityReportGoldenVectorsPublishedAndReadWithoutRecollection` выполняет
семь эталонов ACT-01…ACT-07 через worker, реальную тестовую PostgreSQL, Report gRPC
и HTTP. После публикации контрольный источник меняется, повторные ответы сравниваются,
проверяются чужой/истёкший контекст и доступ исходного гостя после входа.
Для агрегатного ACT-04 материализуются коммиты с эквивалентными недельными счётчиками.
ACT-06 получает независимое доказательство последней даты согласно условиям эталона.
Отдельный тест проверяет сохранение неизвестности при отсутствии этого доказательства.
Настоящий Git и границы обхода проверяются тестами сборщика #18490.

Бинарный round-trip тестирует все поля опубликованных примеров report-zero,
report-null и report-partial, включая presence скаляров и вложенные модели.
Интеграционные тесты БД используют REPOPULSE_TEST_DATABASE_URL и отдельную временную БД.
