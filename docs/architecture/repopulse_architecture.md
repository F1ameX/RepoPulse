# Архитектура RepoPulse — действующая основа MVP

Нормативный источник — [документ №916, редакция 1.1 от 19.10.2026](https://ai.nsu.ru/documents/916).
Уточнения: [№888 ред.3.0.1](https://ai.nsu.ru/documents/888), [№889 ред.2.3](https://ai.nsu.ru/documents/889),
[№909 ред.2.3](https://ai.nsu.ru/documents/909), [план №917 plan-mvp-1.2.1](https://ai.nsu.ru/documents/917).
Эта страница — локальный указатель и краткое изложение, не вторая спецификация.

```text
Frontend (React/TypeScript)
  → HTTP API Gateway
       → gRPC Auth: сессии и проверенный контекст
       → gRPC Report: сохранённый отчёт и история
       → интерфейс компонента Analyzer: проверка/создание/статус

Analyzer в существующем backend
  → очередь и состояния в PostgreSQL
  → адаптеры Git / GitHub / OSV
  → пять анализаторов и 12 метрик
  → детерминированный Score и каталог рекомендаций
  → HTTP AI-адаптер выбора допустимого объяснения / fallback
  → неизменяемые снимок и отчёт в PostgreSQL
```

Gateway не содержит сканеры и формулы Score. Сбор, анализаторы, Score и AI — модули
Analyzer; дополнительные микросервисы и брокер очередей не вводятся.
Хранилище — одна PostgreSQL со схемами auth/analyzer/report.
Миграции и контракты разделены по владельцам. Отдельный запуск Analyzer
и его транспорт этим контрактным тикетом не объявляются реализованными.

Область MVP: публичный GitHub, активность, документация, признаки тестов,
безопасность (включая прямые зависимости npm/Maven/Go), CI/CD; гостевой запуск,
аккаунты, собственная история, основания и ограничения, правила рекомендаций и
AI-выбор текста. Код/тесты/сборка чужого репозитория не исполняются.

Очередь берётся атомарно. Повтор owner/request_id не создаёт второй job.
Неизвестная актуальность или новое окно требуют нового анализа; URL/SHA/TTL
по отдельности недостаточны. Отчёт и снимок сохраняются до completed.
Открытие истории читает исходный результат без сети и нового анализа.

У аккаунта и исходного гостя могут одновременно действовать разные контексты.
Новые запуски после входа принадлежат аккаунту, прежний guest report доступен
только при сохранённом действующем guest context; в account history он не переносится.
